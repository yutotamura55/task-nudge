## Issue #45 端末テストの不安定さ（2026-10-25〜26）

- 原因：入力欄にフォーカスすると、システムがソフトキーボードの領域（WindowInsets の IME）を非同期に変え、`imePadding()` の画面が縮む。Compose のテストはこれを待たず、遅い環境ではタップ、スワイプ、表示の判定が配置の動いている最中に当たっていた。経緯と測定値は [Android 開発記録の13節](android-development-notes.md) に書いた。
- 対応：文字を入力した後は `closeKeyboard()` でフォーカスを外し、領域が 0.5 秒続けて消えてから操作する。フォーカスが必要なスワイプは `awaitKeyboardAreaSettled()` の後で位置を測る。失敗時の端末の状態を `FailureDiagnostics` でログに残し、`device-smoke.sh` が失敗後にそのログを表示する。端末のキーボードを無効にする案は、領域だけが渡ることと、APK のインストールで既定のキーボードが有効に戻ることから採らなかった。
- 確認：ローカルのエミュレーター（API 35、CI と同じ 320×640）を毎回データを消して起動し、エミュレーターと Gradle を CPU 2個に制限して `device-smoke.sh` を実行した。直す前は6回中3回失敗した。最終版では10回すべて44件成功した。2回目のレビューの修正後にさらに5回を実行し、すべて44件成功した。GitHub Actions は利用枠の上限で実行できていない。
- レビュー：全差分を Codex CLI の `gpt-6.1-sol`（推論 high、`--sandbox read-only`）で2回レビューした。モデルはセッション記録で確認した。1回目の指摘は、キーボード設定を戻す処理の欠陥3件（一覧取得の失敗、後から有効になったキーボードの漏れ、言語の設定の消失）、待機の時刻を読む順序、待機の漏れ2か所、古い bash への対応。キーボードを無効にする処理は後に取りやめ、それ以外はすべて直した。2回目の指摘は、日本語変換の確定直後の表示判定で待機が漏れていたことと、通知のテストで失敗時の記録が後片付けの後になっていたことの2件で、どちらも直した。
