# Issue #14: 同じ日に再び通知するタスク

## 利用者が求める動作

「水を飲む」のようなタスクで、完了後も指定時間が経てば同じ日に再び通知する。ユーザーとの確認では、間隔は前回の通知時刻や固定時刻ではなく、最後に完了した時刻から数える。

## 設計

- タスクごとに「日ごと」または「時間ごと」を選ぶ。日ごとは従来どおり 1〜365 日、時間ごとは 1〜24 時間。既存タスクは日ごとのまま移行する。
- 時間ごとのタスクは最後の完了時刻から指定時間が過ぎるまで通知候補と手動完了から外す。未完了の通知は従来どおり全体の通知間隔で繰り返せる。通知時間帯と全体の通知間隔は共通設定を使う。
- 同じ現地日に複数の完了履歴を保存する。日ごとのタスクは同じ現地日の重複完了を防ぎ、時間ごとのタスクは間隔内の連打を防ぐ。DB の一意制約は同じタスク・現地日・完了時刻の重複を防ぐ。
- 通知候補が複数あるときの優先順位は既存の「通知していないタスクを先、次に最後の通知が古いタスク」を維持する。複数回分の通知を後からまとめて作らない。
- DB version 2 から 3 に移行して時間間隔を追加し、完了履歴の索引を更新する。version 1 からは 1→2→3 の順に移行する。

## 確認する境界

同日 2 回目の完了、間隔の直前とちょうどの時刻、日付またぎ、日ごとの既存動作、古い DB の移行、画面からの登録、通知の完了後の再配信をテストする。実機の省電力制御下で正確な配信時刻は保証できない。
