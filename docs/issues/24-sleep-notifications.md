# Issue #24: スリープ中の通知予約

## 目的と確認範囲

端末の画面が消えている間も、設定した間隔に近い時刻で通常通知を投稿できるようにする。通知がスマートウォッチに表示されるかは、スマホとウォッチの通知連携設定にも依存する。

ユーザーからは、スリープ解除時に通知が届くと報告された。通知履歴での投稿時刻は未確認のため、当該事象がアラームの遅延か通知表示・転送の遅延かは確定していない。

## 観測と原因の検討

2026-10-17、接続した Android 14 端末の `dumpsys alarm` では、既存アプリの次回 `RTC_WAKEUP` 予約に約11分の実行幅が付いていた。コードは `AlarmManager.setAndAllowWhileIdle()` を使用していた。Android の説明では、この予約は Doze 中の実行を許すが、時刻は不正確で、省電力制御時の遅延上限は保証されない。したがって、報告された遅延の一因になり得る。[Android のアラーム選択指針](https://developer.android.com/develop/background-work/services/alarms)

原因をたどると、(1) スリープ中は OS が処理時刻を調整できる、(2) アプリが時間幅のある予約を使っていた、(3) Issue #9 では特別な権限を避ける設計を選んだ、(4) Issue #24 ではスリープ中の通知をより重視する要件になった、という関係がある。(1) が今回の個別の遅延を起こしたかは、通知履歴の時刻がないため推定である。

## 変更

- Android 12 以降は「アラームとリマインダー」の許可がある場合に `setExactAndAllowWhileIdle()` を使用する。許可がない場合と、権限確認後に拒否された場合は従来の `setAndAllowWhileIdle()` を使用する。Android 11 以前は特別な許可を必要としない。
- 通知設定画面から Android の特別なアクセス設定を開けるようにする。設定から戻ったときと許可通知を受けたときに予約を更新する。
- 通常通知の内容、完了・保留操作、既存の WorkManager による予備の確認は維持する。正確な予約でもメーカーの省電力制御や OS の制約により、15分ごとの到着を保証しない。[Android の正確なアラームの説明](https://developer.android.com/develop/background-work/services/alarms)

## 検証

- 単体テストで、許可時の正確な予約と未許可時の時間幅のある予約を確認した。
- `scripts/check.sh` で単体テスト、lint、debug APK と端末テスト APK のビルドを確認した。
- 普段使いのアプリとは別 ID の検証用アプリを接続端末へ入れ、設定画面の端末テスト1件を実行した。Android 14 の `dumpsys alarm` で、未許可時は約22分の実行幅、許可時は `window=0 exactAllowReason=permission`、許可取り消し後は再び時間幅のある予約を確認した。検証用アプリは削除し、元のアプリのデータ領域が残ることを確認した。
- 端末を実際にスリープさせたままの通知到着時刻と、スマートウォッチへの転送は未検証。利用端末の通知履歴とウォッチ側の設定を併せて確認する必要がある。
