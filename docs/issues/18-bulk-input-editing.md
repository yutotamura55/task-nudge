# Issue #18: 「まとめて追加」の入力操作

## 対象と再現

Issue #13 で、改行だけをタスクの区切りにするために複数行の `EditText` の自動折り返しを止めた。Issue #18 では、長い行を編集するときの表示と横スクロールを直す。

接続した Pixel 4a (5G) で修正前の入力欄を検証した。

- 長い行の末尾にカーソルを置くと、入力欄内を右へスワイプしても `scrollX` は 306 のままで、先頭側の文字を表示できなかった。カーソルを移す必要があるという報告を再現した。
- 末尾で IME の変換中カーソルを変換文字列の先頭側に置くと、変換文字列の右端は入力欄の右端を 96 px 超えた。確定前の文字が隠れるという報告を再現した。変換中カーソルが文字列の末尾にある場合は隠れなかった。
- 既存の横スワイプテストは画面端付近からスワイプを始め、端末の「戻る」ジェスチャーに取られる場合があった。テスト開始位置を入力欄の内側へ移した。
- 修正後、カーソルを末尾に保ったまま先頭側へ横スワイプし、再び文字を入力すると、新しい文字が画面外のままだった。入力再開時にカーソル位置へ表示を戻す必要があった。

## 原因と修正

1. 長い行が画面幅を超えるのは、折り返しを止めた結果であり、Issue #13 の要件どおり。
2. `EditText` のスクロール位置は通常カーソルを表示するように動くため、カーソルが末尾にある状態では指で先頭側へ戻す操作が保持されなかった。カーソル操作と表示位置の操作を同じ `EditText` に任せていたことが直接原因。
3. 変換中に IME がカーソルを変換文字列の先頭側に置くと、そのカーソルは見えていても変換文字列の末尾は画面外になる。表示確認をカーソル位置だけで行っていたため、この条件を検証できていなかった。
4. Issue #13 の端末テストは、カーソル位置が末尾にある横スワイプと、変換中カーソルが文字列の先頭にある場合を含めていなかった。確認条件の不足が二つの問題を見逃した再発可能な原因。

横ドラッグ中は `EditText` のカーソル操作を止め、カーソル位置を保持したまま表示位置だけを動かす。タップと縦スクロールは通常の `EditText` に任せる。文字変更後に変換中の文字列がカーソルより先まで続く場合は、その末尾を表示範囲へ移す。入力値・改行・保存形式は変えない。

利用者が長い行の先頭側を見たあと文字入力を再開した場合は、カーソル位置を表示範囲へ戻す。手動で表示を動かす操作と、入力に追従する操作を分ける。

独立レビューでは、変換中の文字列が入力欄より長いときに末尾を表示するとカーソルが隠れる可能性が指摘された。入力欄を超える変換文字列の端末テストを追加し、文字列全体を同時に表示できない場合もカーソルが見えるようにスクロール位置を制限した。

## 確認条件

- 長い行の末尾にカーソルを置いたまま、右へのスワイプで先頭側へ戻れる。
- 横スワイプ後に入力を再開すると、新しい文字とカーソルが見える。
- 変換中カーソルが文字列の先頭側にあっても、確定前の文字列末尾が見える。
- 変換中の文字列が入力欄より長い場合も、カーソルは見える。
- 改行によるタスク分割、横・縦スクロール、日本語変換の継続と保存が維持される。

端末テストは利用中アプリのデータを守るため、一時的な `applicationIdSuffix` を付けた検証用 APK で実行する。この設定はコミットしない。
