# Issue #64: データの書き出しと読み込み

## 目的

署名の鍵が違う版へ移るときは、アンインストールが必要になり、データが消える。
移る前にデータをファイルに書き出し、新しい版で読み込めるようにする。
想定する場面は次の 3 つ。

- debug 鍵の版から Releases のリリース鍵の版へ移る
- 将来、Google の配布経路へ移る
- 控えを取っておく

## ユーザーが決めたこと（2026-10-28）

- ファイルは暗号化しない。タスク名と完了日時は個人情報の類ではない、という判断による。画面と README で、中身が読めることを示す。
- 読み込むと、アプリのデータを全部置き換える。追加（マージ）は重複の判定が要る。空のときだけ読み込む方式は、控えから戻すたびに先にデータを消す手間がかかる。どちらも採らない。

## ファイルの形式

UTF-8 の JSON。最初の 2 つのキーは `format`（`task-nudge-backup`）と `version`（今は `1`）に固定する。
こうしておくと、新しい版のファイルを、知らない項目を読む前に「新しい版」と判定できる。

| キー | 内容 |
| --- | --- |
| `exportedAt` | 書き出した日時（ISO 8601）。読み込みでは書式だけ確かめる |
| `settings` | `startHour`・`endHour`・`intervalMinutes` |
| `tasks[]` | `title`・`recurrenceDays`・`recurrenceHours`（null 可）・`createdAt`・`archived`・`snoozedUntil`（null 可）・`completions[]` |
| `completions[]` | `completedAt`（ISO 8601）・`localDate`（`yyyy-MM-dd`） |

次のものは含めない。

- タスクの ID：読み込むときに振り直す。
- 表示中の通知（`active_reminders`）、最後に通知した時刻、通知の許可を求めたか：その端末の状態で、別の端末では意味がない。

## 安全性の設計

アプリの外に置いたファイルは、他のアプリや人が書き換えられる。読み込むファイルは信用できない入力として扱う。

| 脅威・失敗 | 対策 | 実装 |
| --- | --- | --- |
| 権限が増える | ファイルの場所は Storage Access Framework の選択画面で利用者が選ぶ。ストレージ・INTERNET の権限は足さず、継続的な URI 権限も取らない | `ContentBackupDocument` |
| 大きなファイルでメモリを使い切る | 実際に読んだバイト数で 16 MB に制限する。提供元が申告するサイズは使わない。書き出しも同じ上限で止め、読めないファイルを作らない | `BackupCodec.LimitedInputStream`・`LimitedOutputStream` |
| 壊れた・細工された JSON | 不正な UTF-8、知らないキー、重複キー、欠けたキー、型の違い（数値の代わりの文字列など）、末尾の余分なデータ、コメントを拒む | `StrictJsonReader` |
| 範囲外の値 | 画面の入力と同じ規則で検証する。タイトルの長さ・前後の空白、繰り返しの範囲、通知時間、日時の範囲（1970〜9999 年）、完了記録の重複、タスク 10,000 件まで | `validateBackup` |
| 途中で失敗して中途半端なデータが残る | ファイル全体を検証してから書く。置き換えは ReminderEngine の Mutex と 1 回のトランザクションで行う | `replaceWithBackup` |
| 前のデータの通知が残る | 置き換えで `active_reminders` を消す。確定後の照合で、DB にない OS 通知を取り消す。通知 ID は AUTOINCREMENT なので再利用されない | `ReminderEngine.reconcileLocked` |
| ファイルの中身が漏れる | エラーの表示とログには理由の種類と何件目かだけを出し、タスク名などを含めない | `InvalidBackupException`・`displayMessage` |
| 書き出しの失敗でファイルが残る | 失敗したら、途中まで書いたファイルの削除を試みる | `TaskViewModel.exportBackup` |

## 画面の状態

画面の操作の状態は、`2026-10-01-command-boundaries.md` の決まりに従い、画面の session ごとに持つ。

- 書き出し：`Saving` → `Committed(BackupExported)`。結果は「閉じる」を押すまで表示する。
- 読み込み：`Saving`（読んで検証する）→ `ConfirmingImport`（件数の確認）→ `Saving`（置き換え）→ `Committed(BackupImported)`。
- 検証済みのファイルの内容は、選んだ画面の session だけが確定できる。別の画面へ移ると破棄する。

## 検証

- 単体テスト：
  - `BackupTest`：値の検証。
  - `BackupCodecTest`：往復、拒む入力、上限。
  - `ReminderEngineTest`：置き換え、通知の取り消し、失敗時に元のデータが残ること。
  - `TaskViewModelTest`：確認の前に変えないこと、session、エラー文にファイルの中身を含めないこと。
- 検査を外すとテストが失敗することを確かめた。重複キーの検出を外すと 1 件、サイズの上限を外すと 2 件が失敗した。
- 画面テスト（API 35 エミュレーター）：
  - 設定画面から開けて、「戻る」で設定画面に戻ること。
  - 確認ダイアログの件数、「やめる」と「置き換える」、結果の表示中はボタンが押せないこと。
- エミュレーターでの手動確認（2026-10-28、API 35、画面 320×640）：
  1. タスクを 2 件作り、1 件を完了した。
  2. Android のファイル選択画面で「Downloads」に書き出した。ファイルは 752 バイトで、中身は上の形式どおりだった。
  3. タスクを 1 件足して 3 件にした。
  4. 書き出したファイルを読み込んだ。確認ダイアログの件数（ファイル 2 件・完了 1 件、今 3 件）を見て「置き換える」を押すと、書き出した時点の 2 件と完了 1 回に戻った。
  5. 繰り返しを 400 日に書き換えたファイルを読み込んだ。「1件目のタスクの繰り返しが範囲外です」と表示され、データは変わらなかった。書き換えたタスク名は logcat に出なかった。
  - 手動確認で、結果のメッセージがボタンより下にあり、小さい画面ではスクロールしないと見えないことが分かった。結果の表示中はボタンが押せないため、理由が見えない状態になる。そこで、エラーと同じ画面上部に移した。
- 実機（メーカー製の端末、Google ドライブなどの提供元）での確認は未実施。
