# Task Nudge

忘れがちな小さな行動を、ひとつずつ思い出すための Android アプリです。[元のアイデア](https://github.com/yutotamura55/my-software-ideas/issues/11)をもとにした個人用 MVP です。アカウント、通信、広告、分析機能はありません。

## 使い方

1. 「＋」からタスク名を入力して保存します。名前だけなら毎日繰り返します。繰り返しは 1〜365 日から設定できます。
2. 通知が必要なら、画面の「通知を有効にする」から許可してください。許可しなくても、一覧・詳細・手動完了・履歴は使えます。
3. 通知の「完了」でその日の実行を記録します。「保留」はそのタスクを 1 時間後から再び候補にします。通知をタップするとタスク詳細が開きます。
4. 一覧または詳細の「完了」からも記録できます。同じタスクを同じローカル日付で完了できるのは 1 回です。過去の未完了分は作りません。

最後の完了日から繰り返し日数が経ったタスクが候補になります。保留期限に達したタスクを優先し、それ以外は前回の完了が古い順に選びます。通知は最大 1 件です。初期設定は **09:00 以上 21:00 未満、30 分間隔**。設定画面で時間帯と 30/60/120 分間隔を変更できます。保留期限や通知間隔は「その時刻に必ず鳴る」予約ではありません。

## インストール

対応は **Android 8.0（API 26）以上**です。GitHub Actions の成功した `Android` 実行から `task-nudge-debug` artifact をダウンロードし、ZIP 内の `app-debug.apk` を端末へ転送して開きます。開発用 APK なので、端末で「この提供元からのインストール」を許可する必要があります。USB デバッグを使う場合は `adb install -r app-debug.apk` でも入れられます。APK は署名済みストア配布版ではありません。

Android 13 以上では、明示的に「通知を有効にする」を押したときだけ通知権限を求めます。拒否後は端末のアプリ通知設定から変更できます。Android 8〜12 でも端末全体または通知チャンネルを無効にすると通知されません。

## 通知とデータについて

通知の確認には WorkManager を使います。省電力設定や端末メーカーの制御により通知は遅れることがあります。アプリを強制停止した後は、手動で開くまで通知処理を再開できません。再起動や日付変更後の動作は端末により異なるため、重要な時刻のアラームとしては使わないでください。

完了時の端末ローカル日付を履歴に保存します。後でタイムゾーンを変えても保存済みの日付は書き換えません。タスクと履歴は端末内の SQLite にのみ保存し、バックアップと端末移行の対象から除外します。端末メーカーごとのバックアップ挙動には差があります。アンインストールすると記録は失われます。エクスポート、完了取消、全件削除はこの MVP にはありません。

## 開発と検証

JDK 17、Android SDK 36、Gradle 8.13（同梱 wrapper）、AGP 8.13.2、Kotlin 2.2.21 を使います。`scripts/check.sh` は core/app 単体テスト、lint、debug APK と instrumentation APK のビルドを実行します。Android 端末またはエミュレーターを 1 台接続して `scripts/device-smoke.sh` を実行すると、Compose と実通知の instrumentation テストを実行します。手順と端末上の確認項目は [docs/testing.md](docs/testing.md)、今回の開発で得た再利用可能な知見は [docs/android-development-notes.md](docs/android-development-notes.md) を参照してください。
